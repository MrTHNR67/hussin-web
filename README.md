# سياج | رفيق الطاقة الشمسية

نسخة أولية قابلة للتشغيل والتعديل في VS Code، مستوحاة من تسلسل الشاشات والألوان الظاهرة في فيديو التصميم.

## التشغيل

1. ثبّت Node.js 18 أو أحدث.
2. افتح هذا المجلد في VS Code.
3. افتح الطرفية داخل المجلد وشغّل:

   ```bash
   npm.cmd install
   ```

4. انسخ `.env.example` إلى ملف جديد اسمه `.env` في المجلد نفسه.
5. ضع مفاتيح الخدمات التي تريد تفعيلها في `.env`:

   ```env
   ANTHROPIC_API_KEY=ضع_مفتاحك_في_الخادم_فقط
   ANTHROPIC_MODEL=claude-haiku-5-5
   CLAUDE_USER_DAILY_LIMIT=10
   CLAUDE_GLOBAL_DAILY_LIMIT=100
   GOOGLE_CLIENT_ID=معرّف_عميل_ويب_من_Google_Cloud
   VAPID_PUBLIC_KEY=
   VAPID_PRIVATE_KEY=
   VAPID_SUBJECT=mailto:your-email@example.com
   PORT=3000
   SIYAJ_DATA_DIR=
   DATABASE_URL=
   DATABASE_PASSWORD=
   DATABASE_SSL_CA=
   SUPABASE_URL=
   SUPABASE_SECRET_KEY=
   SUPABASE_STORAGE_BUCKET=siyaj-media
   ```

   لإعداد Google، أنشئ OAuth Client من نوع Web application، وأضف `http://localhost:3000` إلى Authorized JavaScript origins، ثم انسخ Client ID إلى `GOOGLE_CLIENT_ID`. لا تضع مفاتيح الخدمات في `public/app.js` أو أي ملف يُرسل إلى المتصفح.

   لتفعيل Push، ولّد مفاتيح VAPID مرة واحدة واحفظ `VAPID_PUBLIC_KEY` و`VAPID_PRIVATE_KEY` في إعدادات خادم Render، وضع بريد تواصل صالحاً في `VAPID_SUBJECT`. سجّل الدخول، حدّد موقع النظام وفعّل تنبيهات الغبار والرياح من الإعدادات على كل جهاز مطلوب. الموقع يحتاج HTTPS أو `localhost` وإذن الإشعارات. على Render Free استخدم جدولة Supabase الموضحة أدناه؛ فالمؤقت الداخلي يعمل أثناء تشغيل الخادم فقط. دعم Push على الهاتف يعتمد على المتصفح؛ وقد يتطلب تثبيت الموقع على الشاشة الرئيسية.

6. ابدأ الموقع:

   ```bash
   npm.cmd start
   ```

7. افتح [http://localhost:3000](http://localhost:3000).

## استخدام الحساب نفسه على اللابتوب والهاتف

في النسخة المهيأة بـSupabase، تُحفظ بيانات الحساب والإعدادات وسجل الفحوصات في Postgres، وتحفظ الصور والفيديوهات في حاوية Supabase Storage خاصة. تُزامن البيانات عبر خادم سياج عند نجاح الاتصال. لكي تظهر البيانات على جهاز آخر، يجب أن يفتح الجهازان نسخة الموقع المنشورة نفسها عبر عنوان HTTPS واحد، ثم يسجل العميل الدخول بالحساب نفسه. الملفات التي لم تُزامن بنجاح تبقى على الجهاز الذي أضيفت منه. عنوان localhost يعمل على الجهاز الذي يشغّل الخادم فقط.

محلياً، يستخدم التطبيق SQLite ومجلد `data/uploads`. على Render Free، يمكن استخدام Supabase لحفظ قاعدة البيانات والملفات خارج خادم الموقع؛ أضف قيم `DATABASE_URL` و`SUPABASE_URL` و`SUPABASE_SECRET_KEY` إلى Environment في Render. عند وجود القيم الثلاث معاً، ينشئ التطبيق جدول الحالة وحاوية الملفات الخاصة تلقائياً. تُخزن الصور والفيديوهات في Supabase Storage، بحد 25 ميغابايت للملف و250 ميغابايت لمرفقات الحساب. لا تضع رابط قاعدة البيانات أو المفتاح السري في مجلد `public` أو ترسلهما في رسالة.

## النشر على Render Free مع Supabase

1. ارفع ملفات المشروع إلى مستودع GitHub خاص. ارفع ملفات المشروع فقط، ولا تضف ملف `.env` أو مجلد `data` إلى المستودع.
2. أنشئ مشروعاً في Supabase.
3. من **Connect** في Supabase انسخ رابط قاعدة البيانات من **Session pooler** إلى `DATABASE_URL`. خدمة Render تتصل عبر IPv4؛ استخدم Session pooler على المنفذ `5432`، وليس Transaction pooler. يمكنك ترك موضع `[YOUR-PASSWORD]` في الرابط وإضافة كلمة مرور قاعدة البيانات الخام في `DATABASE_PASSWORD` داخل Render؛ يحل الخادم هذه القيمة محل كلمة المرور في الرابط ويعالج ترميز رموزها تلقائياً. هذا الخيار اختياري: إذا تركت `DATABASE_PASSWORD` فارغاً، يستخدم الخادم كلمة المرور الموجودة في `DATABASE_URL`، ويلزم أن تكون رموزها مرمزة بصورة صحيحة لرابط URL. لا ترسل كلمة المرور في المحادثة أو تحفظها في GitHub.
4. من إعدادات Supabase انسخ **Project URL** و**Secret API key**. المفتاح السري يمنح الخادم صلاحية عالية، لذلك استخدمه في Render فقط ولا تضعه في ملفات الواجهة أو GitHub. إذا كان مشروعك يعرض المفتاح القديم، ضعه في `SUPABASE_SERVICE_ROLE_KEY` بدلاً من `SUPABASE_SECRET_KEY`.
5. في خدمة Render افتح **Environment** وأضف `DATABASE_URL` و`SUPABASE_URL` و`SUPABASE_SECRET_KEY` (أو `SUPABASE_SERVICE_ROLE_KEY` للمفتاح القديم). أضف `DATABASE_PASSWORD` إذا اخترت إدخال كلمة المرور الخام منفصلة. عند الحاجة إلى شهادة جهة إصدار للتحقق من اتصال قاعدة البيانات، ضع شهادة CA التي يوفرها Supabase بصيغة PEM في `DATABASE_SSL_CA`، كاملة مع سطري البداية والنهاية؛ يمكن استخدام أسطر فعلية أو رموز `\n` بين الأسطر. اترك هذا المتغير فارغاً إذا لم يلزم تخصيص شهادة؛ يبقى التحقق من شهادة SSL مفعّلاً. اترك `SUPABASE_STORAGE_BUCKET` على `siyaj-media` أو حدّد اسماً آخر للحاوية الخاصة. لا تضف `PORT`؛ Render يضبطه تلقائياً.
6. احفظ المتغيرات وانتظر ظهور **Live**. يبدأ التطبيق بإنشاء قاعدة الحالة وحاوية المرفقات الخاصة عند التشغيل.
7. افتح رابط `onrender.com` عبر HTTPS على اللابتوب والهاتف، ثم سجّل الدخول بالحساب نفسه.
8. إذا استخدمت تسجيل Google، أضف عنوان الموقع المنشور كاملاً إلى **Authorized JavaScript origins** في إعداد OAuth على Google Cloud.

تطبق خطة Supabase حدوداً للسعة والاستخدام، وقد يُوقف المشروع المجاني لقلة النشاط؛ يمكن استئنافه من لوحة Supabase. عند نجاح الربط تكون قاعدة الحسابات والمرفقات خارج القرص المؤقت في Render، فلا يعتمد حفظها على بقاء ذلك القرص بعد إعادة نشر الموقع. يجب الاحتفاظ بنسخ احتياطية مستقلة لقاعدة البيانات ولملفات Storage؛ فالنسخة الاحتياطية لقاعدة البيانات لا تتضمن محتوى الملفات. راجع [الاتصال بقاعدة Supabase](https://supabase.com/docs/guides/database/connecting-to-postgres)، و[إتاحة الخدمات على الخطة المجانية](https://supabase.com/docs/guides/deployment/going-into-prod#availability)، و[النسخ الاحتياطية](https://supabase.com/docs/guides/platform/backups).

يعالج خادم سياج على Render تسجيل الدخول والجلسات؛ يحفظ المتصفح ملف ارتباط `HttpOnly`، وتُحفظ سجلات الجلسات مع الحسابات في Postgres. المرفقات في [حاوية خاصة](https://supabase.com/docs/guides/storage/buckets/fundamentals#private-buckets)، ويقرأها خادم سياج بعد التحقق من الحساب. الربط يستخدم قاعدة البيانات وStorage فقط، ولا ينقل تسجيل الدخول إلى Supabase Auth. يظل Google هو خيار الدخول الخارجي الحالي. تحليل Claude يحتاج إعداد API في الخادم كما هو موضح أدناه؛ تفعيل إشعارات Push يحتاج مفاتيح VAPID والجدولة التالية.

### تفعيل تحليل Claude

الربط البرمجي مهيأ، أما التفعيل الفعلي فيحتاج مفتاح API صالحاً ورصيد استخدام في Claude Console. لا يبدأ التحليل المدفوع بمجرد رفع الملف أو فتح الموقع؛ ينفذ فقط عند ضغط العميل زر تحليل الألواح أو قراءة الفاتورة بعد تسجيل الدخول.

1. أنشئ أو افتح حساب [Claude Console](https://platform.claude.com/)، واضبط رصيد API وحد إنفاق مناسباً. API منتج منفصل عن استخدام محادثات Claude. قد تتضمن بعض خطط Max وTeam رصيد API شهرياً يمكن المطالبة به بربط مؤسسة Console؛ راجع [طريقة دفع استخدام API](https://support.claude.com/en/articles/8977456-how-do-i-pay-for-my-claude-api-usage). لا يكفي تسجيل الدخول إلى موقع محادثة Claude لتفعيل الموقع.
2. أنشئ مفتاح API وضعه في `ANTHROPIC_API_KEY` داخل **Environment** في Render فقط، أو في `.env` المحلي عند التطوير. لا تضع المفتاح في GitHub أو `public` أو المتصفح أو رسائل المحادثة.
3. النموذج الافتراضي `claude-haiku-5-5`، ويدعم الصور والنص والمخرجات المنظمة. يمكن تغيير النموذج في `ANTHROPIC_MODEL` إلى نموذج Claude متاح لحسابك ويدعم هذه الخصائص.
4. حدود التطبيق الافتراضية: `CLAUDE_USER_DAILY_LIMIT=10` طلبات للحساب يومياً، و`CLAUDE_GLOBAL_DAILY_LIMIT=100` لجميع الحسابات، وطلبان متزامنان في عملية الخادم. تحليل الألواح وقراءة الفاتورة يشتركان في الحد. هذه حدود لعدد الطلبات وليست سقفاً نقدياً مضموناً؛ اضبط حد الإنفاق أيضاً في حساب Anthropic. قد تُحتسب محاولة طلب فاشلة ضمن حد التطبيق.
5. احفظ إعداد الخادم وأعد نشره. يظهر التحليل كغير مفعّل إذا كان المفتاح غائباً؛ لا يختلق الموقع نتيجة بديلة باسم Claude.

في طلب الألواح، يرسل الخادم حتى **8 صور أو لقطات ثابتة إجمالاً** من المرفقات، مع وقت كل لقطة إن توفر، ووقت التصوير المؤكد، واتجاه الشمس المحسوب، وقياسات اتجاه الألواح التي أدخلها العميل، وقراءة الجو المتاحة. لا يرسل الفيديو الكامل أو الصوت إلى Claude، ولا يرسل إحداثيات GPS الدقيقة إليه. تُرسل الإحداثيات إلى Open-Meteo لجلب بيانات الطقس والحساب الشهري. وقت التصوير لا يُستنتج من اسم الملف ولا يُفترض أنه وقت الرفع.

قراءة الفاتورة طلب مستقل يرسل صورتها إلى Claude لاستخراج فترة الفاتورة والاستهلاك والمبلغ والرسوم وسعر وحدة الطاقة إن كان مطبوعاً بوضوح. يعرض العميل القيم، ويعدلها ويؤكد التعرفة قبل استخدامها. لا تستخدم الفاتورة وحدها لقياس إنتاج الألواح أو الخسارة، ولا تستنتج التعرفة بقسمة إجمالي المبلغ على الاستهلاك؛ فالإجمالي قد يتضمن رسوماً وضرائب ومتأخرات.

### جدولة التنبيهات على Render Free

احفظ سراً عشوائياً بطول32بايت على الأقل في `SIYAJ_JOB_SECRET` على Render، ونفس القيمة في Supabase Vault باسم `siyaj_alert_job_secret`. بعد تفعيل Supabase Cron، شغّل `deploy/supabase-alert-schedule.sql` بصلاحية مالك المشروع. تُستدعى الوظيفة كل ساعة لتسمح بإعادة المحاولة، بينما يحمي سجل كل لوح الفحص اليومي ومهلة14يوماً بين تنبيهات الغبار. تحذير الحرارة تابع لتنبيه الغبار فقط. يُرسل توقيع HMAC صالح لمدة15دقيقة بدلاً من السر نفسه في طلب HTTP؛ لا تضع مفاتيح Supabase الخاصة داخل ترويسات pg_net.

جدول `public.app_settings` هو مصدر الحدود العددية الحالي ويُقرأ في كل عملية دون إعادة نشر. `public.panel_analyses` يحفظ خسارتي الغبار والحرارة في أعمدة منفصلة nullable، مع حمايةRLS ومنع وصول أدوار المتصفح. إعدادات الحساب والجلسات تبقى في `siyaj_app_state`. تعديل الحدود مخصص لمالك المشروع عبر لوحة Supabase.

إيقاف الجدولة مؤقتاً ممكن من Supabase Cron عبر تعطيل وظيفة `siyaj-daily-alerts`. نجاح إرسال Push يعني قبول خدمة المتصفح للرسالة؛ ظهورها الفعلي يعتمد على إعدادات الجهاز والمتصفح. لا يُطلب إذن الإشعارات تلقائياً عند فتح الموقع، ويُلغى الاشتراك عند الخروج من الجهاز.

## ما يتضمنه

- مقدمة تلقائية بلا زر: يبقى الشعار كبيراً في الوسط 3 ثوانٍ، ثم ينتقل إلى زاوية الشريط العلوي خلال نحو 0.58 ثانية ويبقى هناك قرابة ثانيتين قبل ظهور شاشة الدخول. لوحة الألوان عاجية وبيج وبرتقالية مع درجات فحمية دافئة، من دون أخضر.
- معالج إعداد من أربع خطوات: بيانات البيئة والموقع، بيانات الألواح والمرفقات، فاتورة الكهرباء، ومراجعة البيانات.
- لوحة متابعة عربية RTL بألوان عاجية وبيج وفحمي وبرتقالي، وحالة النظام والطقس والغبار وفقد الطاقة والتوصيات.
- بحث عن المدن وتحديد GPS. يسمح المتصفح بالموقع على `localhost` أو موقع يعمل عبر HTTPS، ويجب منح إذن الموقع.
- عند اختيار الموقع، يجلب الطقس درجة الحرارة والرطوبة وحالة السماء، ويملأها تلقائياً في النموذج. يُستخدم PM10 لتقدير مؤشر غبار أولي؛ هذا ليس قياساً مباشراً لكمية الغبار الملتصقة بسطح اللوح، ويمكن تعديله يدوياً.
- إرفاق الصور أو فيديو قصير للألواح. يُرفع الملف الكامل إلى حاوية المرفقات الخاصة عند المزامنة. عند طلب التحليل وتفعيل Claude، يرسل الخادم حتى ثماني صور أو لقطات إجمالاً لوصف الغبار والظل والملاحظات الظاهرة. يعرض التقرير مواضع اللقطات الزمنية؛ لا يصف ذلك كتحليل لكل لحظة من الفيديو.
- قراءة صورة فاتورة الكهرباء بواسطة Claude بعد طلب العميل، مع عرض الحقول المستخرجة للمراجعة والتعديل، وتأكيد تعرفة وحدة الطاقة يدوياً.
- حساب خسارة الشهر المختار بمقارنة إنتاج شمسي متوقع وإنتاج فعلي لنفس الفترة عند إدخالهما. عند غياب القراءات الكافية، يستخدم نموذج الطقس ومواصفات النظام لتقدير الإنتاج، ويعلن الافتراضات ونقص البيانات. لا يساوي استهلاك فاتورة الشبكة إنتاج الألواح، ولا تُضرب قيمة الفاتورة في نسبة الغبار. لا يعرض مبلغ خسارة شهرياً بلا تعرفة وحدة طاقة مؤكدة.
- حفظ نسخة مؤقتة من بيانات النموذج في `localStorage`، ومزامنة الحساب والإعدادات وسجل الفحوصات عبر الخادم إلى Supabase عند تهيئة الربط. تُزامن الصور والفيديو بين الأجهزة عبر Supabase Storage الخاص، وتُخزن نسخة في IndexedDB على كل جهاز. حدود التطبيق للمرفقات: 25 ميغابايت للملف و250 ميغابايت للحساب؛ هذه حدود الكود وليست سعات خطة Supabase.
- سجل فحوصات، وضع ليلي، تنبيهات Push للغبار والرياح، وتنبيه حرارة يصاحب تنبيه التنظيف عند الحاجة، وتصدير نسخة من البيانات.
- تنبيه الغبار يعتمد على رياح متوقعة مع رطوبة منخفضة، أو توقع PM10 بوصفه مؤشراً للغبار الجوي، أو تأخر التنظيف دون أمطار معتبرة. يُمنع تكراره خلال 14 يوماً. خدمة الطقس الحالية لا تعطي علماً مباشراً باسم «عاصفة غبارية»، لذلك يستخدم سياج توقع الجسيمات الجوية بديلاً معلناً.
- تنبيه الحرارة يُرسل مع تنبيه التنظيف فقط عندما تتجاوز الحرارة المتوقعة 40°م ولم يُسجل تنظيف خلال الأيام الثلاثة السابقة.
- عند تسجيل التنظيف، يحفظ سياج توقيته في قاعدة البيانات المضبوطة. تعرض لوحة المتابعة وصفحة «تقرير النظام» تفصيل الفقد إلى حرارة وغبار وظل بإجمالي تقديري، وتبقى الخسارة الشهرية منفصلة بقيمتها. يُجلب الجو من Open-Meteo عند التحليل، ويستخدم الحساب إعدادات `app_settings` القابلة للتعديل.
- تفكيك الفقد مع شرح السبب: الحرارة من نموذج حراري وقت الفحص، والغبار من التغطية المرئية أو القيمة المدخلة يدوياً أو مؤشر الجسيمات الجوية، والظل من التغطية المرئية، ثم إجمالي تقدير لا يتجاوز 100%. يعرض التطبيق الفقد اللحظي بسبب حرارة الألواح وقت الفحص منفصلاً عن الخسارة الشهرية المحسوبة من الإنتاج المتوقع والإنتاج الفعلي، ويصرّح أن النسب تقديرية وليست قياساً كهربائياً مباشراً. القراءات المحفوظة قبل هذا التفصيل تُكمل من المدخلات الحالية عند عرضها.
- صفحة «البلاغات والشكاوى» ترسل البلاغ إلى فريق الصيانة على `shathaalbaraa67@gmail.com` عبر `POST /api/complaints`، مع تحقق من الحقول وحدّ للطلبات لكل عنوان IP (يبدأ من 30 ثانية). عند ضبط `SIYAJ_SMTP_*` يرسله الخادم مباشرة عبر SMTP، وإلا يعيد رابط `mailto` ويفتح التطبيق بريد الزائر بالنص الجاهز، مع زر مشاركة/نسخ نص البلاغ. تُحفظ نسخة من كل بلاغ في سجل البلاغات على الجهاز.
- صفحة «تقرير النظام»: تقرير منسّق بالعربية والإنجليزية يضم ملخص الأداء وتفصيل الفقد وبيانات النظام والطقس وقت التقرير والتوصية. زر «تنزيل PDF» يفتح نافذة الطباعة بوضع التقرير فقط لحفظه PDFاً، وزر «طباعة» للورق، وزر «مشاركة» يستخدم Web Share أو ينسخ نص التقرير لصقه في بريد أو واتساب لدى شركة الصيانة.
- شريط تقدم رفيع أعلى الصفحة لكل طلب شبكة، وشاشة تحميل تظهر فقط إذا استغرقت استعادة الجلسة وقتاً بعد المقدمة؛ وبعد 10 ثوانٍ تظهر ملاحظة تأخر وزر «إعادة المحاولة».
- رسائل التحقق تظهر داخل الحقل نفسه مع شريط تنبيه داخل النموذج لا يغطي الحقول، وحالة تحديد GPS نصية (مسموح، مرفوض، اتصال غير آمن، تعذّر التحديد، نفاد المهلة) مع اقتراح البحث عن المدينة، وحالة تحديث الطقس في النموذج مع تعطيل زر التحديث أثناء الانتظار. أزرار الجوال أكبر، وتنبيهات التوست تظهر أعلى الشاشة خصوصاً عند فتح لوحة المفاتيح.
- عند إدخال زاوية ميل خارج المدى المُعد في `app_settings`، تظهر رسالة إرشادية في خطوة بيانات الألواح. لا تتكرر لنفس القيمة بعد حفظها، وتظهر إذا تغيرت الزاوية إلى قيمة غير مناسبة.
- الحسابات والجلسات وبيانات الحساب وإعدادات `app_settings` وبيانات اللوح واشتراكات Push وسجلات `panel_analyses` تُحفظ محلياً في SQLite، أو في Supabase Postgres عند ضبط متغيرات الربط. تحفظ المرفقات محلياً في التطوير، أو داخل حاوية Supabase الخاصة على الخادم المنشور. أنشئ نسخاً احتياطية آمنة؛ فهذه البيانات تشمل حسابات ومواقع وملفات العملاء.
- بعد أول تشغيل، يمكن تعديل العتبات داخل جدول `app_settings` باستخدام أداة SQLite مثل DB Browser for SQLite؛ يقرأها الخادم أثناء كل فحص مجدول وحساب تقرير جديد، فلا يلزم تغيير الكود لإعادة معايرتها.
- زر تغيير اللغة في الشريط العلوي للتبديل بين العربية والإنجليزية، مع استمرار نفس الصفحة والبيانات.
- تظهر شاشة الدخول أولاً بعد المقدمة؛ بعد الدخول ينتقل الحساب الجديد إلى الخطوة الأولى، ويعود الحساب السابق إلى بياناته المحفوظة.
- إنشاء حساب باسم مستخدم فريد مع البريد والهاتف وكلمة المرور وتأكيدها. يمكن الدخول باسم المستخدم أو البريد أو الهاتف. يحفظ الخادم كلمة المرور كقيمة مشتقة ومملحة، وتستخدم الجلسة ملف ارتباط `HttpOnly`. يمكن نقل الحسابات القديمة الموجودة في هذا المتصفح عند تسجيل الدخول بها لأول مرة.
- تسجيل Google حقيقي عبر Google Identity Services؛ يتحقق الخادم من Google ID token باستخدام OAuth Client ID الموجود في `.env`.

## حدود التقدير والخصوصية

نسبة الغبار أو الظل الظاهر على السطح تقدير لمساحة مرئية، وليست نسبة فقد كهربائي. الصور العادية لا تقيس زاوية الميل المطلقة أو اتجاه البوصلة أو درجة حرارة سطح اللوح؛ يعرض سياج ملاحظات نوعية، ويحتاج قياسات العميل ومعرفة الموقع ووقت التصوير لحساب العلاقة مع الشمس. اتجاه الشمس لا يحدد درجة حرارة اللوح؛ قراءة الجو ونموذج الحرارة تقديرات منفصلة. جودة الصورة لا تكشف سلامة التوصيلات، ولا يغني التحليل عن فحص فني.

تقرير الشهر يفضل قراءات الإنتاج المتوقع والفعلي لنفس الفترة، ويحسب فرق الطاقة مضروباً في تعرفة مؤكدة لعرض الأثر المالي بالريال العماني. نموذج الطقس البديل يستخدم قدرة النظام والإشعاع وميل اللوح واتجاهه ونسبة أداء مفترضة `PR=0.8` تشمل خسائر الحرارة وغيرها؛ لا يُخصم أثر الحرارة مرة أخرى من ذلك الإنتاج. لا يحوّل مساحة الغبار أو الظل المرئية تلقائياً إلى خسارة شهرية، ولا يفترض استمرار حالة لقطة واحدة طوال الشهر. الشهر الجاري يعرض الفترة المتاحة ولا يصفها كشهر مكتمل. التقديرات ليست مطالبة تعويض أو قراءة من العاكس، والفاتورة وحدها غير كافية لقياس فقد الإنتاج الشمسي.

عند إرسال بلاغ من صفحة «البلاغات والشكاوى» يصل إلى الخادم اسمك ووسيلة تواصلك ونوع البلاغ والموضوع ووصف المشكلة والموقع ومعرّف البلاغ، ثم يُرسل إلى بريد فريق الصيانة (`SIYAJ_COMPLAINT_EMAIL`، والافتراضي `shathaalbaraa67@gmail.com`). لا يحتفظ الخادم بنسخة من نص البلاغ في قواعد بياناته؛ السجل الظاهر في التطبيق محفوظ في متصفحك. مع ضبط `SIYAJ_SMTP_*` تُرسل الرسالة من الخادم عبر SMTP، وإلا لا يغادر النص خادمك وتُسلَّم رسالتك إلى تطبيق بريدك لترسلها بنفسك. تقييد طول الحقول وتحققها يمنع حقن محتوى غير معروف، ويحمي مسار الإرسال حدّ طلبات لكل عنوان IP.

في التطوير دون متغيرات الربط، تُحفظ البيانات محلياً في SQLite داخل مجلد `SIYAJ_DATA_DIR` أو `data`، والملفات في `uploads`. إذا ضُبطت متغيرات Supabase الثلاثة، تُحفظ بيانات التطبيق والحسابات وسجلات الجلسات في Postgres وتُحفظ المرفقات داخل حاوية Storage خاصة. يلزم استخدام قاعدة Supabase نفسها في كل نسخة منشورة حتى تتشارك الأجهزة الحسابات والملفات. تظل نسخة المتصفح للتخزين المؤقت. المرفقات، ومنها الفيديو الكامل، تمر عبر خادم Node إلى Storage عند المزامنة؛ أما Claude فيتلقى الصور واللقطات والسياق المحدود فقط عند تفعيل الخدمة وطلب العميل التحليل، أو صورة الفاتورة عند طلب قراءتها. التفعيل الفعلي معلق على إعداد حساب API ومفتاحه. تحديد الموقع يرسل الإحداثيات إلى Open-Meteo؛ لا تُرسل إحداثيات GPS الدقيقة أو بيانات الدخول إلى Claude. قد تحتوي صورة الفاتورة نفسها على بيانات شخصية؛ يُنصح بحجب الاسم والعنوان ورقم الحساب قبل طلب قراءتها. يخضع تعامل الخدمات الخارجية مع البيانات لسياساتها؛ لا يقدم سياج ضماناً مستقلاً لمدة احتفاظها بالبيانات.

## الملفات

- `server.mjs`: خادم محلي وواجهات الطقس والبحث وتحليل الصور.
- `server/auth.mjs`: إنشاء الحسابات والتحقق من كلمات المرور وجلسات الدخول.
- `server/data-store.mjs`: تخزين الحسابات والبيانات والمرفقات وإعدادات التطبيق والتقارير.
- `server/dust-wind-alerts.mjs`: وحدة تنبيهات Push المجدولة ومكافحة التكرار.
- `server/heat-loss-report.mjs`: وحدة حساب وتخزين خسارة الحرارة.
- `server/complaints.mjs`: تحقق البلاغات وبناء رابط البريد وإرسالها عبر SMTP اختيارياً.
- `server/claude-analysis.mjs`: إرسال الصور إلى Claude، وقراءة الفاتورة، والتحقق من النتائج المنظمة وحدود المدخلات.
- `server/solar-assessment.mjs`: حساب اتجاه الشمس وتقدير إنتاج الشهر وفقد الطاقة وفق البيانات المتاحة.
- `server/weather-data.mjs`: قراءات الطقس والتوقعات وسجل الأمطار.
- `public/sw.js`: استقبال Push وعرض إشعار النظام.
- `public/index.html`: واجهة التطبيق.
- `public/styles.css`: الألوان والتخطيط والحركة والتوافق مع الجوال.
- `public/app.js`: خطوات الإدخال ومزامنة بيانات الحساب والتفاعل.
- `public/assets/logo.png`: الشعار المستخدم في الواجهة.

# ثلاث نسخ + فحوص الصحة
powershell -ExecutionPolicy Bypass -File scripts\start-cluster.ps1

node services/weather/server.mjs

# توليد حمل ثم مراقبة التوسّع
powershell -ExecutionPolicy Bypass -File scripts\load-test.ps1
